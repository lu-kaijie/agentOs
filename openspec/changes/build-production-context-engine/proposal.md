## Why

当前 `agentOs` 已经有可运行的 context bundle 与基础压缩能力，但还停留在“把近期历史截短并拼成摘要”的原型阶段，无法支撑长会话、复杂 coding 任务和真实产品中的连续协作。要往“实际可用产品”靠，系统必须能够在上下文增长到阈值后主动整理记忆，并针对不同类型的信息使用不同的保留与压缩策略，而不是一刀切地截断文本。

## What Changes

- 为 `agentOs` 增加生产导向的上下文生命周期引擎，能在会话长度、工具输出或阶段切换达到阈值时主动触发上下文整理。
- 把当前统一的长历史压缩逻辑升级为类型化压缩策略，对用户约束、任务计划、工具结果、失败记录、代码工作区状态和普通对话分别处理。
- 引入分层记忆结构，至少区分近期对话、当前任务工作记忆、长期用户偏好、工具事实和工作区状态。
- 让上下文选择从“按近期历史拼接”升级为“按任务相关性 + 角色视角 + 预算限制”组合上下文。
- 明确采用混合式压缩路线：结构化事实优先由程序抽取，语义性记忆优先由模型压缩，最终上下文预算与装配由系统显式控制。
- 为上下文决策增加可审计记录，能解释为什么触发压缩、保留了哪些信息、丢弃了哪些信息、当前 prompt 由哪些来源组成。
- 强化会话恢复能力，使 resume 不只恢复聊天记录，还恢复结构化工作状态、未完成任务和最近关键事实。

## Capabilities

### New Capabilities
- `adaptive-context-lifecycle`: 定义上下文何时主动压缩、如何在不同触发条件下进入整理流程，以及如何维护压缩后的生命周期状态。
- `structured-memory-layers`: 定义分层记忆模型，包括近期对话、工作记忆、长期偏好、工具事实和工作区状态等结构化记忆层。
- `type-aware-context-compression`: 定义针对不同上下文类型的专用压缩策略，而不是统一文本截断。
- `context-observability-and-audit`: 定义上下文触发、选择、压缩和恢复路径的可审计记录与可观察性输出。

### Modified Capabilities
- `advanced-context-engineering`: 现有 requirement 需要从“支持压缩或总结”提升到“支持主动触发、类型化压缩、结构化记忆保留和任务相关性选择”。
- `context-policy-runtime`: 现有 requirement 需要从“可配置选择器/压缩器/检索器”提升到“支持分层记忆、预算控制、类型化 reducer 与审计记录”。

## Impact

- 主要影响 `src/agentos/context/`、`src/agentos/app.py`、`src/agentos/runtime/` 与 shell/session 恢复链路。
- 会引入新的结构化记忆模型、上下文触发器、压缩器、预算器和审计记录。
- 会改变模型输入前的上下文组装路径，并补充新的持久化文件格式或状态字段。
- 会增加新的上下文测试、恢复测试和长会话验证流，确保这不只是内部抽象升级，而是真正提升产品连续可用性。
